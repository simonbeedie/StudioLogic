Programming Key Terms

Getting the exact definition right matters in the exam — vague answers don't get marks. This page covers the key vocabulary you need to know, grouped by theme. Read through, tap each "True or False" to check yourself, then complete your Educake homework.

01
Designing solutions

🧠 Algorithms & Design

  • Algorithm — a sequence of steps that can be followed to complete a task.
  • Decomposition — breaking a big problem down into smaller, more manageable sub-problems.
  • Abstraction — removing unnecessary detail from a problem, so you can focus on what matters.
  • Pseudocode — a way of writing an algorithm using code-like structure, without following the exact rules of any one language.
True or False? An algorithm and a computer program are the same thing.
✘ False — an algorithm is the plan (the steps). A program is one way of writing that plan out in a language a computer can run.
02
Storing information

📦 Data & Variables

  • Variable — a named location in memory that can change while a program runs.
  • Constant — a named location in memory that cannot change while a program runs.
  • Data type — tells the computer what kind of value is being stored, e.g. integer, string.
  • Data structure — a way of organising related data together, like an array or a record.
True or False? "Data type" and "data structure" mean the same thing.
✘ False — a data type describes a single value (like an integer). A data structure organises multiple values together (like an array).
03
Controlling the flow

🔀 Control Structures

  • Sequence — instructions that run one after another, in order.
  • Selection — the program makes a decision using IF, choosing which instructions to run.
  • Iteration — the program repeats a set of instructions, using a loop.
True or False? Selection and iteration are the same thing.
✘ False — selection makes a one-off choice (IF). Iteration repeats instructions (a loop). They're often used together, but they are different constructs.
04
Reusable code

🧩 Subroutines

  • Subroutine — a named, reusable block of code.
  • Procedure — a subroutine that does not return a value.
  • Function — a subroutine that does return a value.
  • Parameter — a value passed into a subroutine so it can use it.
  • Return value — data passed back out of a subroutine to the code that called it.
  • Local variable — a variable declared inside a subroutine, only existing while it runs.
True or False? A parameter and a return value do the same job.
✘ False — a parameter sends data INTO a subroutine. A return value sends data back OUT of a subroutine.
05
Checking it works

🧪 Testing & Errors

  • Syntax error — a mistake that breaks the rules of the programming language, e.g. a missing bracket.
  • Logic error — the code runs without crashing, but produces the wrong result.
  • Test data — used to check a program works correctly. There are three types: normal (typical, expected data), boundary (right at the edge of what's allowed) and erroneous (invalid data that should be rejected).
Exam tip: if asked to describe boundary data, you must say it sits at the very edge of the allowed range — e.g. if the range is 1–10, boundary data is 0, 1, 10 and 11.
True or False? A program with a logic error will always crash.
✘ False — a program with a logic error usually still runs, but gives the wrong answer. This makes logic errors harder to spot than syntax errors, which stop the program from running at all.
