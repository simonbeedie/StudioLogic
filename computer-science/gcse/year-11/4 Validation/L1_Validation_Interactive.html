Lesson 1 — Validation: Range & Type Checks

The scenario

A school office system, a farm sensor, a bank app — every one of them accepts data from a user or a device. If that data isn't checked, the system can crash, store nonsense, or worse — let something through that shouldn't be allowed. Validation is how a program protects itself from bad data before it ever gets used.

Validation doesn't check whether data is true — only whether it's reasonable. A validation check could let through a wrong-but-plausible value (like the wrong but valid PIN) — that's a different problem, solved by authentication, which comes later in this unit.

Key vocabulary

TermMeaning
ValidationA check that data entered is reasonable and usable before a program acts on it.
Range checkChecks a numeric value falls between a minimum and maximum.
BoundaryThe edge value of a range — e.g. if the allowed range is 1–10, the boundaries are 0, 1, 10 and 11.
Re-promptAsking the user again for input when their first entry fails validation.

Extension suggestions

      

        
Extension 1 — Handle non-numeric input gracefully
Research Python's try/except so typing "abc" doesn't crash your program — print a friendly message and re-ask instead.

        
Extension 2 — Validate against a list, not just a range
The school only accepts specific intake years: 2018, 2020, 2022, 2024, 2026. Use a linear search over a list to check the entered year is one of these.

        
Extension 3 — Combine with authentication
Extend into a small admissions system: staff log in with a username and password (stored in a dictionary) before validating a student's admission year.
