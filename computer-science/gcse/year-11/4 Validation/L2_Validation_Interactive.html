Lesson 2 — Validation: Length, Presence & Combining Checks

The scenario

Last lesson, one check was enough — a number was either in range or it wasn't. But a username field has more than one way to go wrong: it could be left blank, or it could be too short, or too long. A single check can't catch all of these.

That's why real systems combine checks — testing several conditions within one validation routine, so nothing slips through.

Key vocabulary

TermMeaning
Presence checkChecks that a field has not been left empty.
Length checkChecks the number of characters in a string, using len().
Combining checksTesting several validation conditions within a single routine.
Meaningful error messageA message that tells the user exactly what's wrong, rather than one generic message for every failure.

Worked example


      
The condition combines a presence check (username == "") and a length check (len(username) < 3) with or — either failure alone triggers a re-prompt.

Extension suggestions

      

        
Extension 1 — Reject spaces
Extend your validation to also reject usernames that contain a space.

        
Extension 2 — Check against a list of taken usernames
Use a linear search over a list of already-taken usernames to reject a username that's already in use.

        
Extension 3 — Add a password field
Validate a second field — a password of at least 8 characters — and print a summary once both are valid.
